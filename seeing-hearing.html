Access Lab · Experience 01

Seeing and Hearing Information

Explore how the same library hours become more or less accessible depending on how they are presented.

Note: Some elements in these activities intentionally demonstrate inaccessible content as part of the lesson. Everything outside those activities aims to meet WCAG 2.1 AA standards or better.

Library Hours — Seeing Information

A library website publishes its hours. There’s information in the box below. Try to read it.

Library website — Hours page

Library Hours

Monday–Friday: 8:00 AM – 10:00 PM Saturday: 10:00 AM – 6:00 PM Sunday: Noon – 8:00 PM Holiday hours may vary.

    Try to read the library hours above.

  2. 2

    Try to copy and paste the text from the box above.

    ✓ Copied — the text was always there. It exists in the document; only its color is hiding it from sighted readers.

    Now try a screen reader simulation.

    A screen reader reads text from the document regardless of its visual color or position on screen.

  4. 4

    Reveal the text to sighted readers.

    ✗ Visible to you ✓ Screen reader ✓ Copy / paste

What this reveals

The text was always there, styled white on white. A screen reader reads it aloud, and anyone who knows where to look can copy it to the clipboard. Sighted readers have no way to see it.

White on white is an extreme. Color contrast is a spectrum, and the same combination reads differently depending on text size, screen settings, viewing conditions, and who’s reading. A ratio that works on one screen may fall apart on another.

The grayscale column shows what each combination looks like when color information is removed — approximating what a reader with red-green color vision difference may perceive.

Key ideas

  • Everyone experiences information differently.
  • Context shapes how we perceive information. Small, low-contrast text may be readable up close and unreadable from across the room.
  • We all do accessibility work every day. Choosing fonts, colors, and layouts means making decisions about who can read what we create.
  • Our sense of what is and is not “readable” is calibrated to how we personally experience information.
  • Developing an accessibility practice means understanding the range of ways people interact with information.

Hearing Information

Here we have the same library hours again. What’s different this time? Who can and can’t access the information?

Library website — Hours page image only

Library Hours

Monday–Friday: 8:00 AM – 10:00 PM
Saturday: 10:00 AM – 6:00 PM
Sunday: Noon – 8:00 PM
Holiday hours may vary.

  1. 1

    Try to copy the hours.

    ✗ We can’t select or copy text from an image. The text would need to be retyped manually.
    ✓ Hours copied to clipboard.
  2. 2

    Try a screen reader on this page.

    3. 🔊 Screen reader announces
    “Image.”

    Without a text layer, a screen reader can only announce the element type — not what the content shows.

  3. 3

    Compare: switch to a version with a real text layer.

What this reveals

Both versions look identical on screen. When someone tries to listen, copy the hours to their calendar, or search for “Saturday” on the page, the image version has nothing to offer. A screen reader announces only “Image.” because the document contains no readable text.

Scanning or screenshotting text and saving it as an image removes other ways of interacting with the content beyond looking at it.

Key ideas

  • When we scan or screenshot text into an image, we remove all interactive and auditory access.
  • Alt text gives screen reader users something to hear. Copy/paste and search still require a real text layer.
  • Real text supports listening, copying, and searching. An image file supports only visual access.

What this reveals

The same information. The same visual appearance. One implementation opens all three channels; the other closes two of them.

Using real HTML — a <h3> heading, a <p> paragraph, <button> elements — means the content can be seen, heard, copied, and searched. These aren’t separate accessibility features. They all follow from the same underlying choice: putting real text in the document.

Key standards

WCAG (Web Content Accessibility Guidelines) is the international standard for digital accessibility, developed by the World Wide Web Consortium. Each success criterion is assigned a conformance level: A sets the baseline; AA is what most organizations target; AAA covers enhanced requirements. These two activities covered four WCAG criteria:

Criterion Level What it requires Activity
1.4.3 Contrast (Minimum) AA 4.5:1 ratio for normal text; 3:1 for large text 01 Seeing
1.4.6 Contrast (Enhanced) AAA 7:1 ratio for normal text 01 Seeing
1.1.1 Non-text Content A All non-text content has a text alternative (alt text) 02 Hearing
1.4.5 Images of Text AA Use real text instead of images of text when possible 02 Hearing

The full WCAG 2.1 specification includes 78 success criteria across all three levels.
